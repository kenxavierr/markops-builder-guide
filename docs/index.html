AMPscript

  set @firstName = "Sarah"
  set @city = "Singapore"

AMPscript / Fundamentals / Data Extensions
Lesson 02

Data Extension lookups

Personalization
Read a DE value and reference it in the email

AttributeValue() gets the subscriber key. Lookup() retrieves the first name.

AMPscript 
%%[
  var @SubscriberKey, @FirstName
  set @SubscriberKey = AttributeValue("SubscriberKey")
  set @FirstName = Lookup("ENT.CustomerMaster","FirstName","SubscriberKey",@SubscriberKey)
]%%

Lesson 03

IF, ELSEIF, and ELSE

Decision logic
Show different content by customer tier

AMPscript

  var @customerTier
  set @customerTier = "Silver"
]%%
%%[ if @customerTier == "Gold" then ]%%
  Gold member pricing is active.
%%[ elseif @customerTier == "Silver" then ]%%
  Silver member pricing is active.
%%[ else ]%%
  Standard pricing applies.
%%[ endif ]%%

SQL / Fundamentals / Selecting data
Lesson 05

SELECT and WHERE

Audience preparation
Select and filter records

SELECT chooses fields, FROM identifies the source, and WHERE narrows the audience.

SQL 
SELECT
  SubscriberKey,
  EmailAddress,
  FirstName,
  Country
FROM ent.CustomerMaster
WHERE IsActive = 1
  AND Country = 'Malaysia'
ORDER BY FirstName ASC

SQL / Combining data / JOIN and UNION
Lesson 06

JOIN and UNION

Combine datasets
JOIN customer and order data

A JOIN connects customer and order records.

SQL • JOIN 
SELECT
  c.SubscriberKey,
  c.EmailAddress,
  c.FirstName,
  o.OrderID,
  o.TotalAmount
FROM ent.CustomerMaster c
LEFT JOIN ent.CustomerOrders o
  ON c.SubscriberKey = o.SubscriberKey
UNION regional audiences

UNION ALL requires the same number and order of columns.

SQL • UNION ALL 
SELECT SubscriberKey, EmailAddress, FirstName, Country
FROM ent.Customers_Singapore
UNION ALL
SELECT SubscriberKey, EmailAddress, FirstName, Country
FROM ent.Customers_Malaysia

Reference / Quality checklist
Lesson 08

Best practices

Launch safely
AMPscript and SQL checklist
  • Use clear variable and Data Extension field names.
  • Test AMPscript in preview before sending.
  • Filter early in SQL and validate null values.
  • Prefer UNION ALL when duplicates are acceptable.
  • Use comments, aliases, and predictable target DE names.
